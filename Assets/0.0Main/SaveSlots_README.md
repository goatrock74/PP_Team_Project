# 슬롯 저장 사용법

`0.0MainMenu_F` 씬은 START / SETTING / EXIT로 바로 시작합니다. START → 저장 목록.

- NEW: 0골드로 시작하는 독립된 새 슬롯을 생성합니다. 줄을 클릭하면 게임을 시작합니다.
- BACK / X: 메인 메뉴로 돌아갑니다.
- 쓰레기통 → 삭제?: 해당 슬롯과 백업을 삭제합니다.
- 게임 중 3초마다 자동 저장합니다. F5로 즉시 저장할 수 있습니다.
- 연결된 메뉴/대화/상점의 씬 이동 전, 앱 일시정지 및 정상 종료 시에도 저장합니다.

## 저장 내용

슬롯당 `Application.persistentDataPath/SaveSlots/<ID>.json`에 저장합니다.
임시 파일을 완전히 기록한 뒤 교체하며 직전 저장은 `.json.bak`으로 남깁니다.
주 파일이 손상되면 백업을 읽습니다. 둘 다 읽을 수 없는 슬롯도 삭제할 수 있습니다.

날짜와 시각, 돈, 누적 플레이 시간, 씬과 플레이어 위치, 가방/핫바의 종류·수량·품질 및 선택 칸,
숙련도, 물고기 도감, 낚시 미끼와 남은 사용 횟수, 1회 구매 기록, 씬별 비 상태,
경작/급수 칸, 작물 성장·시듦 상태, 나무·채집물 상태와 재생 대기 시간을 저장합니다.
계절/연도 표시는 기존 TimeManager의 **계절당 5일, 1년 20일** 규칙에 맞춥니다.

밭·인벤토리 등의 기존 직렬화기를 재사용하고, SaveSlotStore가 각 결과를 슬롯 메모리에 모읍니다.
SaveGameSession이 전체 상태를 수집한 뒤 JSON 하나를 기록합니다. 행동별 이벤트 로그는 아닙니다.
강제 종료 시 마지막 저장 이후 최대 약 3초의 진행은 잃을 수 있습니다.

기존 PlayerPrefs 데이터는 삭제/자동 이관하지 않습니다. 메뉴에서 생성한 슬롯에는 이전 데이터가
섞이지 않으며, 슬롯을 선택하지 않고 게임 씬을 직접 실행하면 기존 저장 동작을 사용합니다.
음량 설정은 게임 슬롯과 독립적으로 유지됩니다.

## 씬 연결과 확인

메인 메뉴 씬에는 SAVE 버튼과 SaveSlotMenu 컴포넌트가 배치되어 있습니다.
저장 목록의 스크롤 패널/행은 해당 컴포넌트가 실행 중 생성합니다.
아이템 및 미끼는 Resources/InventoryItemCatalog, 밭 에셋은 FarmSaveManager 목록에 등록되어야 합니다.
새 씬 이동 코드는 `SaveGameSession.LoadScene(index)`를 사용해야 마지막 진행이 먼저 저장됩니다.

확인 순서: NEW 2개 생성 → 첫 슬롯에서 돈/아이템/작물 변경 → F5 → 메인 메뉴 복귀 →
둘째 슬롯의 초기 상태 확인 → 첫 슬롯 복원 확인 → 둘째 슬롯 삭제 → 재실행 후 목록 확인.
Unity에서 NEW/PLAY 및 게임 진입을 직접 확인했고, 돈·날짜·위치·인벤토리의 저장→메뉴 복귀→재진입 통합 검사를 통과했습니다.

## 재검사 도구

- `Tools > Save System > Play Main Menu Only`: 다른 씬을 함께 열었어도 메인 메뉴만 실행합니다.
  실행 종료 후 원래 편집 씬 구성을 유지합니다.
- `Tools > Save System > Run Save Reload Smoke Test`: 독립 테스트 슬롯으로 저장·재진입을 검사합니다.
  테스트 슬롯은 종료 시 삭제합니다. 결과는 `Temp/SaveSmokeResult.txt`입니다.
- `dotnet run --project Tests/SaveSlots/SaveSlotChecks.csproj`: 파일 저장 회귀 테스트 11개입니다.
  Unity 직렬화는 필드 기반 대체 구현을 사용하며 실제 Unity 통합 검사는 위 메뉴에서 수행합니다.

메뉴 복귀 시 파괴된 낚시 오디오/UI 참조 접근, 씬 재진입 시 작물 시계 참조 유실,
백업만 남은 슬롯의 목록 누락, 복구 후 정상 백업 덮어쓰기, 잘못된 JSON 항목의 런타임 접근을 보완했습니다.
